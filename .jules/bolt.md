## 2024-06-06 - O(1) Lookup for Pre-Calculated Database Relationships
**Learning:** During epoch processing (`process_transition_phase_async` in `engine.py`), the previous code evaluated combat interactions and treaty violations by performing deeply nested nested O(N*M) database iterations. In the inner loop, it repeatedly fetched nodes and players from the database (`session.get()`) to identify if one faction attacked another. Even with caching, executing nested loops to re-evaluate the same state dynamically scales poorly as node and player counts grow.

**Action:** Map state relationships in a single pass. During the initial pass that processes combat actions (`node_actions`), identify and record the relationship mappings (e.g. `(attacker_faction_id, node_faction_id)`) into a memory-efficient Set like `hostile_actions`. In subsequent passes, such as when evaluating Accord violations, rely on the O(1) set lookup rather than re-querying and iterating through actions and database rows again.
